# The remastered layer

An optional layer above the exact port: things the original never did (upscaled textures, widescreen) live here and nowhere else.

## The rule

**Classic code changes only for fidelity.** Code that draws, simulates or lays out what the original does (everything outside `packages/lego-racers-web/src/modules/remastered/`) changes only to match `LEGORacers.exe` or `GolDP.dll` better. A remastered feature never edits it, except to add a neutral extension point (a hook or an option that says nothing about any feature, and with no extension registered changes nothing). The pixel trace, render trace and golden cases run Classic and must stay green unchanged.

## Where it lives

`packages/lego-racers-web/src/modules/remastered/` (module-first, public `index.ts`). It is a module and not a package: it implements interfaces the web package defines (`src/shared/viewer-extensions/`), uses Three.js and the DOM, and a package would have to depend on the web package that loads it, a cycle. The simulation packages stay free of it.

- `src/shared/viewer-extensions/`: the extension points and the registry (`registerViewerExtension`). Today: `onTextureCreated` (a texture was made from an original bitmap), `onPictureCreated` (a 2D picture, menu image or font sheet, was made; it may be replaced by a bigger one and the viewer scales source rectangles by its size factor), `getMenuSurfaceScale` (resolution of the menu surface relative to its 640 x 480 design), `getSoundReplacement` (a recording to play for an archive sound or tune), `getRaceDisplay` (how the race is laid out: stage size, pixel ratio, HUD design size, HUD command mapping), `getRaceRenderPass` (work to run before each frame of a race is rendered, given the renderer, camera, track scene and the track's group), `getCarDrawing` (a complete car, body, chassis and wheels, in place of the original's, from a champion's body code or a built design), `getDriverDrawing` (a complete driver in place of the original's) and `getEffectModelDrawing` (something to draw in place of the model the original draws for an effect: the power-up and enhancement bricks on the track). A car or a driver the layer has no complete model for is the original's, never mixed; see [remastered-ldraw-racers.md](remastered-ldraw-racers.md).
- `modules/remastered/services/`: `high-definition-texture` (texture packs), `widescreen-display`, `development-texture-server` (the Vite dev route), `remastered-registration` (what `?hd` registers, and the developer panel's choices).

- `modules/remastered/services/real-shadows/`: sun, shadow map and the track's shadow-catching materials; see [remastered-shadows.md](remastered-shadows.md).

## How it is loaded

`main.tsx` imports the module dynamically only when `import.meta.env.DEV` and the URL has `?hd`; a production build has no such import, so none of it is bundled. The developer panel (also development only) offers the Textures choice, which reloads the page with `?hd=<pack>`. Races are recorded for replay with the header marked `isRemastered` (the layer changes drawing and sound only; see [session-replay.md](reverse-engineering/session-replay.md)).

## What it does today

- **Textures**: `?hd=<pack>` swaps each texture for `<LEGO_HD_TEXTURES_ROOT>/<pack>/<archive path>.png` (default root `~/textures/lego-racers`, default pack `ultrasharp`) once loaded, keeping the original's alpha.
- **Widescreen**: the race canvas fills the window at `devicePixelRatio`. The camera keeps the original's 65 degree vertical field of view, so the horizontal one widens (Hor+), and the culling frustum uses the real aspect. The HUD is laid out for the biggest 4:3 area at window height (at native resolution) and each command is then anchored: right third to the right edge, middle third to the centre, left third stays; bottom half to the bottom edge; the pause dimmer stretches over the window. Whether a centred text counts as centred is decided from its start position (**hypothesis**: good enough for the HUD's texts, not exact). Menus stay 4:3 (letterboxed).
- **LDraw cars**: with `?hd`, cars built from bricks are drawn from the official LDraw parts library (`~/ldraw`, served by the dev server) through the extension point `getBuiltCarDrawing`; the developer panel's **Bricks** choice switches back to the original's mesh. See [remastered-ldraw-cars.md](remastered-ldraw-cars.md).

- **Look presets**: `look=manual|photo|instructions|toon|game|retro` changes how the LDraw plastic is made (physical plastic, or a stylised shading model, edge treatment, colour handling); see [remastered-ldraw-cars.md](remastered-ldraw-cars.md) and [remastered-ldraw-styles.md](remastered-ldraw-styles.md). `studlogos=0` (developer panel **Stud logos**) draws plain studs everywhere.
- **Real shadows**: with `?hd` the cars, wheels, drivers, power-up bricks, projectiles and hazards cast soft shadows onto the prelit track, and the original's blob shadows are hidden (`shadows=classic` brings them back, `shadows=scenery` lets the static scenery cast too). See [remastered-shadows.md](remastered-shadows.md).

## Judging LDraw work

**A replacement is done when its fidelity score passes.** `pnpm run ldraw-fidelity [filter] [--drafts] [--sheet N] [--strict]` measures every LDraw replacement the layer makes against the original it replaces, with numbers instead of eyes (no screenshots to look at, so an agent can iterate cheaply): `pnpm run ldraw-fidelity RRCM --drafts` re-measures one car in a few seconds. It needs the original files and the LDraw library (`~/ldraw`) and skips without them. Code: `modules/remastered/services/ldraw-fidelity/`, page `ldraw-fidelity.html` on a dev server of its own (port 5410 or the next free one), in headless Chrome on SwiftShader, so the numbers do not depend on the machine.

- **Items** (about 1,100): every brick with an LDraw part (`LDRAW_BRICK_MAPPINGS`) and every composite (`LDRAW_COMPOSITE_MAPPINGS`), alone in the colour the gallery uses; the 12 chassis (the recipe in `~/ldraw-models/chassis/` against the game's chassis brick; no recipe scores 0); the power-up and enhancement bricks on the track (default look); every champion car in `~/ldraw-models` (and with `--drafts` every `drafts/<CODE>*.ldr`), body and wheels at rest; the wheels of every chassis of `CHASSIS.CMB`; every driver of `DRIVERS.DDB` and every hat, face, torso and pair of legs of the catalogue (on Rocket Racer's figure, `1 28 15 18 0`, the part in its slot), each in four poses: seated (race clip 9), steering (clip 6, 200 ms in), standing (the main menu's `LEGOMAN`, clip 0) and menu idle (`RSANIM` clip 4, `breath2`, one second in). A champion seated in the race is his fixed model, as the race draws him.
- **Same scene**: the original (the Classic model object, the race's lights: ambient 255) and the replacement (the layer's own drawing code, unchanged) are built in the same frame with the same pose and skeleton state, each alone. Four orthographic cameras (front from +x, side from the left, top, three quarters) are framed on both together, 200 x 200 pixels each, no antialiasing. Per view a silhouette pass (white, both sides) and a flat colour pass (the replacement's materials swapped for unlit ones of the same colour and picture; edge lines hidden; the plain-stud level of a body) are read back.
- **Numbers** per item: the silhouettes' intersection over union per view; the 3D offset of the centre of area (least squares over the views) in LDraw units, x forward, y left, z up; the bounds' centre offset and size ratio per axis and the scale (their geometric mean); the mean CIE76 ΔE where both cover; attachment points in LDraw units: wheel centres (the original's wheel pieces on their bones against each LDraw wheel's bounds), for a driver the head, the top of the head and hat, both hands and the seat (bottom of hips and legs) from the original's bones against the minifigure's part holders, for a chassis the built bricks' grid against the real base's studs (`getGridOffset`, the shift every built brick gets), each game wheel's hub (the middle of its inner face, from the chassis's wheel model at rest, `getWheelMounts`) against the nearest face of the base, and the share of the chassis's building cells (its attachable footprint cells, shifted with the grid) that land on a stud of the base's deck (`getFootprintCoverage`).
- **Score** (0 to 100, pass at 80): silhouette 50 (IoU 0.95 full, 0.5 nothing), centroid 15 (0 to 10 LDU), scale 10 (up to 30 %), colour 15 (ΔE 5 to 30), attachments 10 (0 to 10 LDU); a part an item cannot measure drops out and the others share its weight. The original's bricks are flat-topped (the studs are a picture), so a perfect LDraw brick, whose studs stand 4 LDU higher, scores about 92, not 100.
- **A chassis is scored on how it holds the car, not on its shape.** A recipe is a real LEGO car base the user chose on purpose; the game's chassis brick is the whole lower body of the car, which no real base looks like, so its silhouette and colour said nothing about the recipe (every chassis scored 0 to 23). A chassis's score is: wheel hubs 40 (mean distance 0 to 10 LDU: does the base reach the wheels where the game puts them), brick grid 30 (shift 0 to 10 LDU: do the built bricks stay where the game puts them while sitting on studs), building cells 30 (all on a stud full, half nothing: does every cell a player builds on hold a brick). The views are still drawn and listed, for people.
- **Output**: the console line per item (and the full numbers when five or fewer are measured), [remastered-ldraw-fidelity.md](remastered-ldraw-fidelity.md) (by kind, and the 100 worst), `reverse-engineering/ldraw-fidelity/fidelity.json` (every item, not committed; a filtered run updates only its items) and, with `--sheet N`, `worst.png`: the N worst, for people (grey both, red only the original, blue only the replacement, then the flat colours). `--strict` exits 1 when a measured item fails.

## HD coverage trace

**Every racer the game draws is the layer's when the models folder has a model for it.** `pnpm run hd-coverage` (part of `pnpm run traces`; needs the original files, the LDraw library `~/ldraw`, the models folder and Chrome, and skips without them) drives `?hd` through every place a racer is drawn and fails on a car or driver the original draws although the layer could. Code: `modules/remastered/services/hd-coverage/`; the page is `/?hd&hd-coverage` on a development server of its own (port 5420 or the next free one), in the pixel trace's headless Chrome (`src/shared/trace-browser/`). `HD_COVERAGE_PLACES=garage,time trial` limits the run; every place's numbers go to `packages/lego-racers-web/.hd-coverage/results.json`.

- **Models**: the trace copies the models folder (`LEGO_LDRAW_MODELS_ROOT`, default `~/ldraw-models`) to a scratch folder and serves that, so nothing the layer does can touch the real one. Whether a car "has a model" is the layer's own index (`index.json`): a champion's `<CODE>.ldr`, a built car's chassis recipe; a driver always has one (a minifigure of the library).
- **Places** (`hd-coverage-places.ts`): the main menu figure; the racer select of a circuit, a single race and a time trial (the turntable car and the standing driver); the race select cinemas (the champion's figure); the garage's car builder and driver editor, and both screens opened directly; the versus racer select; the seven circuit introductions, the four award cinemas and the three won-car cinemas; a single race (the player and five computers), the first race of a circuit, a versus race of two players, a time trial with the champion's ghost, and one where a finished run's ghost drives beside it. Menus run the real front end with scripted keys (the pixel trace's timing) and the player's car from the quick-build save (`QBUILD.LRS`, a design); races are started by the game session as the menus start them.
- **Calls**: the layer's extension is wrapped (`hd-coverage-recorder.ts`): every `getCarDrawing` and `getDriverDrawing` call is kept with its request (a champion's code or a design's chassis; a driver's model name or part bytes), whether the folder has the model, whether a drawing came back and whether it failed later (`onFailed`, or a throw). Before a censused frame the harness waits until every drawing has a mesh or has failed (at most 4 minutes).
- **Census** (`hd-coverage-census.ts`): `Scene.onBeforeRender` is replaced, so every scene any WebGL renderer of the page draws is seen, whatever path drew it. Each visible object is either a drawing a call returned, or an original instance group (`createInstanceGroup` names its mesh file and world): a champion's body (`<CODE>.GDB`), a chassis's wheels (`*JMW.GDB`), a champion's race driver (`*PELVIS.GDB`), a built car or figure (the mesh builder's `built` in `MENUDATA\PIECEDB` or `MENUDATA\PARTDB`), a cinema's own champion car (`CR_CAR.GDB`, `RRCAR.GDB`) or figure (`GUY1`, `DUMMY01`, ...), or anything else (listed in the results, for a reader who looks for a racer the classification missed).
- **Every part of every model** (the place `Every model of the folder, part by part`, `model-part-check.ts`): each car of the models folder is drawn alone by the layer at rest, and every part line of its main file (`1 <colour> <matrix> <part>.dat`) must reach the screen where the file puts it. The file's parts are parsed alone with the same library and detail, carried into the drawn body's frame, and at least half of each part's triangle vertices must be vertices the drawing draws (within 0.05 LDraw units; the merge keeps every vertex where it was), so a part that is dropped (merge, detail level, taken out by category) or moved is `dropped`, and one whose vertices are there but hidden or fully transparent is `invisible`. Wheels and the figure's own parts are skipped (they are their own drawings). Found and fixed by it: KKCM's two spears (`93789.dat`, `Minifig Accessory`) were taken out of the body with the minifigure (`racer-model-parts.ts`).
- **Every driver on its seat** (the place `Every driver on its seat`, `driver-seat-check.ts`, `driver-seat-judgement.ts`): each of the 20 champions' drivers and the quick-build save's driver in a garage car on every chassis the folder has a recipe for, at the seat point of the racer's appearance (the chassis's `vehiclePoint`), in the race's seated (clip 9) and steering (clip 6, 200 ms in) poses. The original's torso (its torso bone's corners) and the LDraw driver's (the drawing's torso holder, given the pose the race gives it) are measured sideways in the car's frame, and the LDraw one must be within 3 LDraw units of the original's. The LDraw car's steering wheel (`3829c01`, `3829` or `30663`, through the chassis recipe it refers to) is printed beside it, and a note names a model whose wheel is more than half a stud to the side of the seat (the models are the user's, so a note, not a failure). Measured 2026-10-13: every LDraw driver sits on the original's seat (0.1 LDU seated, at most 1.8 steering, where the figure leans about the hip axle); JTchas0 and BVBCHA0 seat the driver a stud to the car's left (20.9 and 20.2 LDU: left-hand drive, as the original's steering wheel on those chassis), so a model with its wheel on the centre line shows the driver beside it (the JTchas0 recipe, wheel at -0.5). The reference sheets mark the seat (a green ring and a line of numbers) so models put the wheel there.
- **Verdict** (`hd-coverage-judgement.ts`), for each original racer part of a place: `no_model_file` (allowed), `hook_not_called` (the viewer drew it on a path that never asks the layer), `hook_returned_no_drawing`, `drawing_failed`, `drawing_not_shown` (a drawing exists but the original still shows). Wheels count only when the layer drew their car and the original's wheels still showed. Each line is printed with `FAIL`, `ok` or `gap`.
- **Known gaps** (`hd-coverage-gaps.ts`): racers the layer has no path for yet, pinned by place, kind and key so the list only shrinks. A gap that is no longer found fails the trace until it is removed. Today: the full-screen cinemas, which draw their worlds' own copies of the champions' cars (in a frame and scale of their own: `VV_CAR.GDB` is the race's car at 1/64, centred on the body; `CR_CAR.GDB` lies along y) and figures (skeletons named per file), not the race's models.
- **Found and fixed by it**: the time trial's champion ghost (`GHOST.WDB` is Veronica Voltage's `vvcm`, `vvjmw` and `vvpelvis`) was drawn without asking the layer (`hook_not_called` for `VVCM` and `VVPELVIS`); `race-viewport` now asks for it as for a champion racer.
- **Not covered**: split screen (the viewer draws one viewport, the versus race's second player is a car in it) and replays (played back by the emulator's command line, not drawn by the viewer).

## Building the cars by hand

`/ldraw-builder.html` on the dev server (`pnpm run dev`) is a builder for the models folder (`LEGO_LDRAW_MODELS_ROOT`, default `~/ldraw-models`). Code: `modules/remastered/services/ldraw-builder/`.

- **Queue**: the 12 chassis recipes (`chassis/<CHASSIS>.ldr`, edited in the recipe frame) and then the 20 champions' cars (`<CODE>.ldr`), each one whole model: chassis and body, everything but the wheels, which the game keeps drawing (spinning and steering) on the wheels of the chassis the champion drives. Progress (done of 32) is kept in `<models>/builder-progress.json`; any item can be opened from the list. An item starts from its file in the folder, else empty; an older car file that places a chassis recipe (`1 16 … rrchas0.ldr`) gets the recipe's parts as its own editable parts where the line put them, and Done writes it flat. **Start from** (grouped Cars, Chassis, Backups/drafts) loads another file of the same name (a draft or a backup) instead, or, for a car, copies another champion's car in (its parts become the item's own, a chassis recipe it places flattened) or a chassis recipe's parts where the game puts that chassis (no link to the recipe).
- **Reference**: the original's model at rest as the race draws it (the fidelity harness's `createOriginalObject`): a champion's whole car (its body model holds the chassis) and wheels, or the chassis brick with its wheels, in the car's frame. Side by side with the same camera, as a ghost over the build, or off (`G`). See-through cylinders mark the game's wheel mounts (`W`, shown on every item).
- **Building**: the library's parts (`/__development/ldraw-builder/parts.json`, the first line of every `parts/*.dat`, moved and sub parts left out) as picture tiles (each part drawn once in the chosen colour, `builder-thumbnails.ts`, as it scrolls into view), found by number or words or from the shortlist's tabs (bricks, plates, tiles, slopes, wedges, car bases, wheels and car parts, windscreens); the library's brick colours. Building is modal: a picked part is in hand and follows the cursor as a see-through preview on the studs, a click places it (it stays in hand), Esc puts it down. With an empty hand a click selects (Shift adds), a drag moves the selection along the stud grid. A chassis needs no base part: the game only uses where the wheels sit (the guides) and the stud tops; **Start from** also offers an empty model.
- **Stud alignment** (`builder-placement.ts`, `builder-studs.ts`, `builder-snapping.ts`): each part's studs, footprint and bottom are read from its library geometry (subfiles and primitives followed, every stud primitive, turned as its matrix turns it). A part goes down with its anti-studs on the studs under the cursor: under its own top studs, or for a part whose few studs sit between its anti-studs (the jumpers 3794b, 15573, 87580, the cone, the dish) where its footprint puts them, half a stud off. It stands on what is under its studs (a pin hole, a wheel holder, a curved brick's front), handles, clips, wheel pins and a bracket's leg beside them hanging lower; a hollow shell (a windscreen's stud plate) and a part without studs (a tile, a wheel) on its lowest point. The cursor's nearest stud gives the grid, so studs at several levels (car bases, inverted slopes) each offer their own. Every key edit but a fine nudge snaps the selection as a whole by its lowest part: the arrows, a drag, R and T rest it on what it moves over (when it rested), ⌘↑ ⌘↓ keep it on that part's plate grid, Option arrows move it off the grid on purpose and the next plain move snaps it back; R turns about the middle of the selection's footprint. `builder-alignment.spec.ts` checks every palette part, turned four ways, on a 3001 and a 3034, a 3001 on each of its studs, and every key combination from four camera angles, with the real library (where `~/ldraw` or `LEGO_LDRAW_ROOT` is).
- **Controls** (Mac first, `builder-shortcuts.ts`, listed on the page and in the `?` overlay): two-finger scroll orbits, Shift pans, a pinch zooms (Option drag orbits, Option Shift drag pans; a plain drag never moves the camera). R and Shift R rotate, the arrows move a stud as the camera looks, ⌘↑ ⌘↓ a plate (Shift a brick), ⌫ deletes, ⌘C ⌘V ⌘D copy, paste, duplicate, ⌘A selects all, ⌘Z and ⇧⌘Z undo and redo, E or Option click takes a colour (Shift E the whole part), 1 to 9 quick colours (a swatch or quick colour repaints the selection, undoably), Shift A or Option Shift click selects every part of the colour under the cursor (a whole chassis recoloured in two clicks), ⌘S is Done, F frames, G and W toggle the original and the wheel guides. Letters never fire while typing in the search.
- **Done** posts the model to `/__development/ldraw-builder/save` (dev server only): the file it replaces is copied to `drafts/backups/<name>-<time>.ldr`, the model is written, the item is marked done and the next unfinished one opens. The game reads the file at its next load.
- **Limits**: one model file per item (`.ldr`; sub-models other than a chassis recipe and type 2 to 5 lines are kept as they are, not shown); parts rotate about the vertical axis only; nothing is kept in the browser, so leaving an item asks before dropping unsaved work.

## Adding a remastered feature

1. If Classic needs a way to ask, add a neutral extension point to `ViewerExtension` (name it for what happens, not for the feature), call it from Classic where it happens, and make it a no-op with no extension registered.
2. Implement the feature in `modules/remastered/services/`, with a co-located spec, and register it in `remastered-registration.ts`.
3. Run `pnpm run ci`: the Classic traces prove Classic did not move.
4. Check `pnpm --filter @lego-games/lego-racers-web run build` and that the build output has no remastered code.

## Menus, UI text and audio (`?hd`)

- **Menus at native resolution**: the front end draws on a canvas of `640 x 480 x scale`, where the scale is the device pixels the menu covers per design pixel (quarter steps, at most 8). Every blit, fill and glyph is drawn through a transform by that scale; the 3D backdrops, figures and cinemas render at the same resolution.
- **Menu art and UI text**: menu images (`MENUDATA\*.BMP`), the menu font sheets (`MENUDATA\ENGLISH\*.BMP`), and the race HUD's images and font sheets (`GAMEDATA\COMMON\*.BMP`, `...\ENGLISH\*.BMP`) come from the texture pack. Glyph and source rectangles are in the original's pixels and are multiplied by the picture's size factor. The original's colour key becomes a smooth alpha (bilinear, sharpened) at the pack's resolution. Pictures show the original until the pack's has loaded.
- **Targa effect textures**: the nine `.TGA` textures swap like the bitmaps (path based, `.png`); their alpha is a gradient, so it is stretched bilinearly instead of nearest.
- **Loose `LEGO<n>.BMP`**: `LEGORacers.exe` `FUN_00435f20` and `FUN_0042e720` (callers `FUN_00435c00`, `FUN_0042d510`) look for the first `LEGO<n>.BMP` that does not exist and write the screen to it: they are the player's screenshots, never read by the game. Nothing displays them, so there is nothing to wire; the pack's `GAMEFOLDER/LEGO*.png` are unused.
- **Audio**: `?hd&audio=<variant>` (a bare `audio` is `resample-48k`) plays `<LEGO_HD_AUDIO_ROOT>/<variant>/<archive path>.wav` (default root `~/audio/lego-racers`) in place of an archive sound (`MENUDATA/SOUNDS/X.PCM` is `X.wav`, `GAMEDATA/COMMON/X.PCM` likewise) or tune (`MUSIC/<name>.wav`). The dev route lists a pack's files at `/<variant>/` so absent sounds cost no request; replacements are preloaded, the original plays when one is not ready yet, and the sample timing is the original's (the recording is decoded at the context's rate over its own duration). The developer panel has an Audio selector next to Textures.

Code: `modules/remastered/services/performance-monitor/`.

The numbers move with where the cars are: the 702 calls, 375 k triangles and 474 k line segments of the third row are the start grid with the cars close to the camera (before: every one of them in the logo detail, each with its own five lights). On an earlier base the same race blocked the page for 11 to 15 s while it loaded. The frame times are those of a fast GPU (the race is CPU bound on it); on a software renderer (SwiftShader, 800 x 450, the weak-GPU proxy) the Manual and scenery frame went from 1070 ms to 205 ms with the cars on the grid. The heap did not shrink (220 to 480 MB before, 230 to 350 MB after: the shared parts are kept for the page's life). The car builder screen draws the same 57 calls, 33 k triangles and 38 k line segments before and after: its car is close, so it is drawn in the logo detail.

**Where the cost was**, in the order of its size:

1. **Logo studs.** `stud-logo4.dat` (the default logo) is some twenty times the triangles and lines of a plain stud; they were 90 % of a car's 84 k triangles and 110 k line segments. A car body is now two models, plain studs and logo studs (`ldraw-car/detail-switch.ts`): the plain one is drawn, and the logo one is built (one at a time, when the camera comes within one and a half times the distance) and drawn only when a stud is at least 14 CSS pixels wide, so the logo is readable (484 LDraw units from the camera at 720 px high, 262 on a 390 px high phone, 969 on a 1440 px monitor). The shadow map always gets the plain one, without edge lines. A close picture (the builder, the showcase, a gallery) looks as before once the logo model has arrived (the gallery render of a car, Manual and Photo, was compared before and after; the plain one shows for the moment the logo one is parsed).
2. **A studio for each car.** Every LDraw car brought five lights, and three.js lights every material of a scene by every light: six cars were 30 lights in each fragment, and each time a car came into view or left it the light count changed and every program was compiled again (37 to 48 programs). The scene now has one studio that the first car moves (`createCarStudio`): the player's car is lit as before, the others by the first car's frame. Wheels and drivers asked the whole scene for its lights every frame (a `getObjectByProperty` over the track); the answer is kept.
3. **Parsing on the page's thread.** The loader's smooth normals and the merge took 4 to 10 s of the page's thread for six cars (the profile's biggest entry). A module worker (`ldraw-worker/`) now parses each model, bakes its occlusion grid, takes a car's wheels out and merges the model, and sends buffers (transferred, not copied); the page makes the materials and the plastic. Without `Worker` the same code runs on the page.
4. **Many small objects.** `mergeModelByMaterial` turns a model into one mesh per material and one line set per edge material, in the model's frame. Wheel, driver and pickup parts are parsed, baked and merged once for each text and detail and shared by every drawing (`detailed-model.ts`); each drawing keeps its own copies of the mesh materials, so a ghost can fade alone. The power-up bricks of a track share one set of materials.
5. **Shaders.** A model's programs are compiled with `renderer.compileAsync` (the browser's compile threads) before it joins the race, once the scene has its lights.
6. **Texture memory.** On a touch screen of at most 1400 CSS pixels (a phone, a tablet) the texture pack's pictures are drawn at most 1024 pixels on a side (the 2560 x 1920 menu pictures are 20 MB each on the GPU); `?maxtexture=<pixels>` sets it by hand, `0` lifts it. A desktop is untouched.
