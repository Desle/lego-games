# Golden trace: the simulation sweep over all 26 races

Companion of [golden-trace.md](golden-trace.md) and [golden-trace-computers.md](golden-trace-computers.md). `computer-racers.golden.spec.ts` runs the original and the port on every race of `LEGORACE.RCB` (26 entries, with the mirrored second passes) and reports, per race, the first divergences of **every** compared field (not only the computers'). Two scenario kinds:

- `COMPUTER_KIND=idle`: the player holds nothing; the computers race (and use their power-ups) alone.
- `COMPUTER_KIND=weave`: the player accelerates and weaves left and right, so the car meets hazards, projectiles and the computers.

```
COMPUTER_FRAMES=7000 COMPUTER_KIND=idle COMPUTER_RACES=igp,rkr COMPUTER_REPORT=/tmp/report.txt \
  pnpm --filter @lego-games/lego-racers exec vitest run --config vitest.golden-trace.config.ts computer-racers
```

`COMPUTER_DUMP=<dir>` writes each scenario (with the keys) as JSON and `COMPUTER_DUMP_ONLY=1` stops there; `computer-debug.golden.spec.ts` with `DEBUG_FIELDS=DIFFERING` prints every field that differs in a frame range. With no race selected and the idle kind, the spec **asserts** the first divergence of each race (`EXPECTED_FIRST_FIELDS`): a fix that removes one makes it fail until the expectation shrinks.

## Result (7,000 frames, about 3 minutes of racing: full laps and, in most races, the whole race)

| Kind  | Races diverging before | Fields differing before | Races diverging now | Fields differing now |
| ----- | ---------------------- | ----------------------- | ------------------- | -------------------- |
| idle  | 23 of 26               | 2,164                   | 0 of 26             | 0                    |
| weave | 26 of 26               | 4,518                   | 4 of 26             | 30                   |

The first sweep (PR #161) left the weaving sweep at 10 of 26 races and 1,355 fields; the second (items 10 to 14) at 4 races and 30 fields, every one of them listed under Still open (the crane and the hammers wait for the cameras' visibility, `rkr2` reads uninitialised stack). The idle sweep matches the original in all 26 races for 7,000 frames before and after.

## Visibility: what the port needs (findings, not ported yet)

Static reading of `LEGORacers.exe` and `GolDP.dll` for the first open item. Nothing here is checked against the emulator yet; the plan at the end says how to check it.

**When the bones are posed.** `Race_RunLoop` (`0x00432540`) runs the state update (`Race_Update` inside it), then `0x00435940`, then `Race_Render` (`0x004354d0`). `Race_Render` returns early (it draws only the effects, `0x0045a7b0`) when race `+0x207c` is set. No instruction writes `+0x207c` with a 32-bit displacement (byte scan), so its writer is still unknown. Otherwise `Race_Render` sets the renderer's camera to viewport 0 (`renderer +0x20` with race `+0x2acc`), and then the race's slot `+0x34` (`0x00435960`) draws the **track world** (`+0x390`) **once**, through world slots `+0x24`, `+0x20`, `+0x28` and `+0x1c` (world vtable from `0x1005690c`; slot `+0x24` is `0x10018230`, every skeleton instance, `+0xa0`, stride `0xf4`). Each viewport whose racer lacks flag `0x10` then draws the sky (`0x0041d0f0`) and the race's slot `+0x38` (`0x00435a00`, the **blended world** `+0x398` among others). So in a one-player race the track world's instances are tested against player 0's camera of this frame, after that frame's update. **Hypothesis:** with several viewports the track world is still tested only against viewport 0.

**The draw test and the pose.** Skeleton instance vtable `0x10056fc8`. Slot `+0x1c` (`0x10028030`) sends the instance to the renderer's slot `+0x94` (`0x10008910`). With instance flag 4 (world keyword `0x4c`) it uses `0x10029500` instead, and with `+0x60`/`+0x62` set it uses `+0xa8`. Both call the same test and pose; the `+0xa8` path is a hypothesis because no function is defined at `0x10008f70`. `0x10008910` calls slot `+0x14` = `0x100240b0` with the camera context (renderer `+0x4c`: the eye, then six planes at `+0x6c`). The test works like this:

1. It takes the sphere through `0x100286d0`/`0x10028710`. The sphere is **cached** at `+0x4..+0x10` and computed again only while its radius is below 0. `0x10023b10` sets the radius to −1 only on a blend or a looping clip's restart. **Open:** whether a frame move also clears the cache.
2. If the first level distance is not `FLT_MAX` (`0x10056fc4`), it takes the first level whose squared distance is not below the eye-to-centre squared distance. Past three levels the instance is not drawn.
3. The level needs a model (`+0x78 + level·4`, so a camera's skeleton is never drawn).
4. `0x1002bc20` tests the sphere against the planes: 0 means culled, 1 partly inside, 2 inside.

When the instance passes, `0x10008880` calls `+0x58(level)` (the level's skeleton) and `+0x5c(level)` = `0x10023580`. That function poses only an animated instance (flag `0x10000`) whose clip index is in range. It **skips the pose when the skeleton's counter (`skeleton +0xc`) equals the instance's stamp (`+0x9c + level·4`)**. Otherwise it increments the counter, stores it as the stamp and writes every bone's translation and rotation from the clip(s); a channel without keys keeps its previous value. `0x10023b10` resets the stamps to −1 every update of an animated instance. The skeleton object (instance `+0x90 + level·4`) is **shared** by every instance that names the same world skeleton. Every skeleton instance in the game's worlds has exactly one level. The shared skeletons are the POWERUP world (magnet, shields, bricks), `dish 16..20`, `ship`/`ship01`, `longship`/`longsh01` (RACEC1R3) and `mosscout`/`mosscot1` (RACEC2R3). None of the hazard readers below uses a shared skeleton, and the shared ones use one animation each.

**The frustum.** The camera frame's update `0x10002160` calls `0x1001bfc0` (or `0x1001c450` when a flag is set: probably the orthographic camera, **hypothesis**) with frame `+0x34` as the output. `0x1001bfc0` works like this:

- **Half-size at the far plane:** tangent = `fptan(fov · [0x10056cec])`; far half-height `+0x24` = far · tangent; far half-width `+0x20` = aspect · that.
- **Half-size at the near plane:** half-height `+0x1c` = near · tangent; half-width `+0x18` = aspect · that.
- **Corners:** the eight corners go through the node's slot `+4` (node vtable `0x1005622c`; the position comes from `+0x40` = `0x10002fe0`).
- **Side planes:** four of them, each from a cross product normalised by `0x1002f530`, at output `+0x6c`, `+0x7c`, `+0x8c` and `+0x9c`. Each plane's offset is minus its dot product with a corner.
- **Near and far planes:** built from the node's forward (`+0x38`) at `+0xbc` and `+0xac`.

The node's orientation is `0x10002a30`: it normalises forward, makes up orthogonal to it and normalises it, and stores right `+0x10`, up `+0x20` and forward `+0x30`. The renderer copies 51 words of the frame (`0x100087e0`) into its context.

**Who reads bones without posing them** (they see the last draw's pose, or another instance's pose of the same skeleton): the crane `0x00490190` (level 0, bone 3), the capture `0x0048e1c0`, the lava `0x0048da10`, the ghost `0x0048cbb0`, the hammer `0x0048be70` and the smoke vent `0x0048e7f0`. The port gives the crane, the capture and the hammer the previous frame's clip (as if they were always drawn) and gives the lava, the ghost and the smoke vent **this** frame's clip, which is wrong whenever they are not drawn and one frame early when they are. **Who poses before reading** (no dependence on visibility): the 3D event `0x0045ebe0`, the 52 event `0x004639d0`, the periodic launcher `0x0048c680` and the camera lock `0x004047b0`. Their pose still counts as the latest pose of their skeleton.

**Plan.**

1. **Bone state.** Each skeleton instance holds the bones' last pose (`{ animation, clip }` or null for the rest pose; **hypothesis:** the bones hold the rest pose before the first pose). Posing an instance writes that state to every instance that shares its world skeleton. All the bone readers in `skeleton-instance-bones` read that state instead of the current clip, which removes the per-hazard `posedClip`/`nextPosedClip`.
2. **Draw pass in `lego-racers`.** Port `0x1001bfc0`, `0x10002a30` (already in `race-camera`), `0x100240b0` and `0x1002bc20` as pure functions. Add `getRaceAfterDraw(raceState, cameraView)`, which poses every track-world instance (and the blended world for viewports without racer flag `0x10`) that passes the test, called like `getRaceWithHazardsAtCamera` after `stepRacePresentation` in the viewer, `race-frames` and the golden trace's port side, which must run the presentation's camera. An alternative is to move the camera into `RaceState`, so that `updateRace` alone stays headless.
3. **Checks.** Differential specs for `0x1002bc20` and `0x100240b0`: buffers like `volume-visibility.differential.spec.ts`, keeping the radius ≥ 0 and a later level without a model so that no virtual slot runs. A spec for `0x1001bfc0` with a node buffer whose vtable is `0x1005622c`. A hook on `0x10023580` in `igp` and `att` weave to confirm which instances are posed per frame. Then the 26-race sweep and the `EXPECTED_FIRST_FIELDS` update.
