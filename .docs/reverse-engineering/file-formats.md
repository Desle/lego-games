# File formats in `LEGO.JAM`

Source: `LEGORacers.exe` and `GolDP.dll` (English, 1999-07-22). Addresses as in [game-map.md](game-map.md); the archive itself is in [jam-archive.md](jam-archive.md). **Confirmed** means the loader and the role were read from code; **hypothesis** means the role is inferred from names and file contents.

## Text and binary resource files

Almost every resource is written in one token language with two encodings. The loader names the file with a text extension ending in `f` (`.wdf`, `.raf`, `.rrf`, …). When the game reads from `LEGO.JAM` (settings `+0x18` non-null) it opens the binary twin, whose extension ends in `b` (`.wdb`, `.rab`, `.rrb`, …), with the binary token reader; otherwise it opens the text file with the text tokenizer. See `Race_LoadRaceDescription` (`0x00431e00`): text reader `0x1fc` bytes (vtable `0x004b0844`), binary reader `0x650` bytes (`0x0044a7e0`, vtable `0x004b0e0c`) plus `TokenReader_SetExtension(".rab")` (`0x0044e7b0`). `Race_LoadAiRoutes` (`0x00433190`) builds the RRB name with last letter `'b'` (JAM) or `'f'` (text). GolDP.dll contains its own copy of both readers (`".txt"` `0x1002fa20`, `".bin"` `0x100302e0`, `SetExtension` `0x10032670`).

### Binary tokens (`BinaryTokenReader_NextToken`, `0x0044aae0`)

All values little-endian. A token byte `< 0x27` is a type or control code; a byte `≥ 0x27` is a format-specific keyword.

| Code          | Payload                                          | Token returned                                                                                                  |
| ------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `0x02`        | NUL-terminated string (at most 63 chars)         | string                                                                                                          |
| `0x03`        | `float32`                                        | float                                                                                                           |
| `0x04`        | `int32`                                          | integer                                                                                                         |
| `0x05`–`0x0a` | none                                             | punctuation; the expect helpers use `0x05` `{`, `0x06` `}`, `0x07` `[`, `0x08` `]` (`0x0044e8c0`–`0x0044e920`)  |
| `0x0b`        | `uint8`                                          | integer                                                                                                         |
| `0x0c`        | `uint8`                                          | integer                                                                                                         |
| `0x0d`        | `int16`                                          | integer                                                                                                         |
| `0x0e`        | `uint16`                                         | integer                                                                                                         |
| `0x0f`        | `int16`                                          | float `value * (1 / 4096.0f)` (`0x004c7070`, set at `0x0044a740`)                                               |
| `0x10`        | `int16`                                          | float `value * (1 / 32.0f)` (`0x004c7078`, `0x0044a790`)                                                        |
| `0x11`        | `int16`                                          | float `value`                                                                                                   |
| `0x12`        | `uint8`                                          | float `value * (1 / 127.0f)` (`0x004c707c`, `0x0044a7c0`)                                                       |
| `0x13`        | `uint16`                                         | keyword with a 16-bit number                                                                                    |
| `0x14`        | `uint16 count`, `uint8 type` (`0x13` + `uint16`) | the next `count` values all have `type` and carry no type byte; `type` may be a macro (`0x17`–`0x26`) or `0x15` |
| `0x15`        | none                                             | expands to the four token types `{7, 4, 8, 8}` (table `0x004b0df8`); purpose not yet seen in data               |
| `0x16`        | `uint8 slot`, `uint8 count`, `count` types       | defines macro `slot` (`0x17`–`0x26`) as a list of types (`BinaryTokenReader_DefineMacro`, `0x0044b020`)         |
| `0x17`–`0x26` | none                                             | the next values follow the macro's type list, without type bytes                                                |

The common shape of a list is `keyword [ count ] { … }` (`TokenReader_ExpectArrayHeader`, `0x0044e940`: `[`, integer, `]`, `{`). The keywords' meanings are per loader (each loader `switch`es on them).

## Small formats

### SRF string table (`StringTable_Load`, `0x0044e2c0`)

```
uint16 stringCount
uint16 characterCount
uint16 offsets[stringCount]        // in characters, from the start of the character block
uint16 characters[characterCount]  // 16-bit characters; each string ends with 0
```

`StringTable_GetString` (`0x0044e540`) returns `characters + offsets[index]` and returns null when `index > stringCount` (note: `>`, not `>=`). Small enough to port as is.

### SBK and LEGOMSC lists (`FileList_Load`, `0x0041a700`)

Text with CR LF line ends: line 1 is a folder prefix (empty in race folders, `Sounds\` in `MENUDATA\GENC0R0.SBK`), line 2 the count, then one file name per line (`.pcm` sound or `.tun` music). Each entry is stored in a 260-byte slot.
