# Save data: the player profile and the saved racers

Source: `LEGORacers.exe` (English, 1999-07-22). Port: `packages/lego-racers/src/modules/save-data`. Anything not proven by code or by the shipped files is marked **hypothesis**. How a session changes the save is in [game-progression.md](game-progression.md).

## Where the original stores it

**In files, not in the registry.** The only registry access in the whole executable is a read of `LangID` (a dword under `HKLM\Software\LEGO Media\Games\LEGO Racers\0.90.000`, `Profile_GetLanguageIndex` `0x0042f0b0`, which maps it to the index of the language list: `0x1d`→6, `6`→5, `7`→3, `0x0a`→1, `0x0b`→10, `0x10`→4, `0x13`→8, `0x14`→7, `0x40c`→2, else 0 = english; `getLanguageIndex`).

The save files live beside the game: `SaveFiles_LoadDefaults` (`0x004332e0`) builds the directory `<DAT_004c7384>\Save\` (the string behind `0x004c7384` is the first of the Gol parameter block's dwords; **hypothesis**: the game's folder) and hands it to the save device (`SaveDevice_SetDirectory`, `0x00450fc0`). The device has 16 slots; slot `n` is the directory `<root>\Save\<n>\` (`0x004512e0`, `_itoa`, `_mkdir` in `0x004511c0`), and the game stores **one file per slot named `LEGORac1`** (`0x004befd8`, no extension). `SaveFiles_LoadSlots` (`0x00443520`) uses the first **two** slots. A missing file (status 8) is created from the defaults (`SaveFile_Create` `0x00443940`, which opens with a size of `0x3e00` bytes and then saves).

Port: `SaveStorage { readSlot, writeSlot, deleteSlot }` over bytes, with an in-memory implementation; the viewer's `createIndexedDbSaveStorage` keeps slot `n` under the key `Save/<n>/LEGORac1` in IndexedDB (every access guarded; without IndexedDB the bytes stay in memory for the session and the game runs on). The save format is the same bytes the original writes, so a save file can move between the two.

## The file

A run of **blocks of `0x80` bytes**: `0x7f` bytes of data and, last, the **sum of those `0x7f` bytes modulo 256** (`SaveFile_GetChecksum` `0x004429d0`; checked in the emulator). `SaveFile_ReadBlocks` (`0x00442910`) compares the byte with the sum of the block it just read and fails with `0x11` otherwise; a short or missing block gives the file layer's own error. `SaveFile_WriteBlocks` (`0x00442840`) zero-pads the last block of a piece of data.

```
header   0x477 data bytes = 9 blocks (file 0x000..0x47f)
racers   n × 0x22d data bytes = n × 5 blocks (0x280 file bytes each), from the position in the header (0x0480)
```

`SaveFile_Parse` (`0x00442770`) reads the header, checks `L`,`R`, takes the racer count and the position of the first racer from it, and reads that many records. `SaveFile_Write` (`0x00442700`) writes `L R <count> 0x80 0x04` and the profile, then the records. `DEFAULT.LRS` and `QBUILD.LRS` hold more records than their header counts (14 of which 4 counted; 25 of which 24 counted); only the counted ones are read.

(and look like records of 35 bytes with eight dwords), while the keyboard configuration of its last record reads as `0x100000cb`, `0x100000cd`, ... (the same values as the presets at `0x004b0624`). **The code's layout is ported** (a file the game writes parses and writes back byte for byte); the shipped default's custom configurations are not meaningful under it, and the front end replaces the ones it does not recognise by presets (`0x0042ee10`, `0x0042ed80`, `0x0042ef00`). The in-memory profile is a different, aligned structure (`Profile_Reset` `0x0042e8a0`, `Profile_LoadFromSaveFile` `0x0042eb60`); the port keeps the file's bytes and never builds it.

### A racer record (`0x22d` data bytes)

A saved player: the name, the colours, the car and the places won.

| Offset  | Size    | Field                                                                                                                                               | Port (`SaveRacer`) |
| ------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `0x00`  | 28      | Name, 14 UTF-16 characters, zero-terminated if shorter (`0x0042b400`)                                                                               | `name`             |
| `0x1c`  | 5       | Colours (`0x0042b330` reads them, the fifth with bit 7 masked: that bit belongs to the record)                                                      | `colorBytes`       |
| `0x21`  | 8       | The car's chassis key (`dachas0`, `ddchas0`, ...; two dwords, `0x0042b380`)                                                                         | `chassisName`      |
| `0x29`  | `0x202` | The car design the builder loads (`CarDesign_Load` `0x0049fb30`): a count and 9-byte piece records (`13 97 ...` is piece `0x1397`)                  | `designBytes`      |
| `0x22b` | 2 (LE)  | **Places won per circuit**: two bits per circuit (0 none, 1 first, 2 second, 3 third); `0x0042b640` keeps the better place, checked in the emulator | `circuitRanks`     |

`DEFAULT.LRS` (`MENUDATA`) holds the default racers (Joan of Kart, Turbo Charger, Scooter, ...), `QBUILD.LRS` (and one per language) the "quick build" cars. `SaveFiles_LoadDefaults` reads them next to the player's files (`default.lrs` `0x004bef94`, `qbuild.lrs` `0x004bef88`).

## What the port does with it

- `parseSaveFile` / `serializeSaveFile`: pure functions over bytes. Parsing and serializing `DEFAULT.LRS` and `QBUILD.LRS` gives back the same bytes (spec).
- `createDefaultProfile(languageIndex)`: `Profile_Reset` (`0x0042e8a0`): everything zero except the racer count option 5, the option bytes `00 80 ff ff 01 <language> 03`, the player controls `00 02 00 00` and `00 02 00 01`.
- `recordBestTime`, `markGhostBeaten`, `unlockCircuit`, `setTrophyFlags`, `recordCircuitRank`, `getIsPartUnlocked`, `getUnlockedCircuitRunLength`: the front end's own updates (`game-progression.md`).
- The size: the open call passes `0x3e00` (124 blocks, room for 23 racers after the header); `QBUILD.LRS` holds 24, so the port does not enforce it (**hypothesis**: a buffer size).

## Verified

`SaveFile_GetChecksum`, `Profile_MarkGhostBeaten` (`0x0042f250`) and `RacerRecord_RecordCircuitRank` (`0x0042b640`) run in the emulator against the port (`*.differential.spec.ts`, 1,500 to 3,000 cases each, including the shift edge cases above 8 circuits). The file layout is verified by reading and writing both shipped files byte for byte. Not verified in the emulator: `Profile_RecordBestTime` (it copies through a wide-string object).

## The front end's save flow (browser port)

The original's screens `0x2d .. 0x31` (`loadall`, `loadcard`, `lccreate`, `saveall`, `savecard`; class `0x00486b30`, one description `SAVEGAME.MIB` with only a picture) are workers that run `SaveSlots_LoadSlot` (`0x00443420`: a slot that is not there, status 8, is created from the defaults by `SaveFile_Create` `0x00443940`; a present one is parsed by `SaveFile_Load` `0x00443980`) and `SaveFile_Save` (`0x004439b0` → `SaveFile_Write` `0x00442700`) for the two slots (`0x00443520`) and show nothing a player chooses. `PICKMEM.MIB` (screen `0xc`, class `0x004846b0`, handler `0x004849e0`) offers the slots and "continue without saving" with console strings (memory card, controller pak); its buttons set `frontend + 0x4bc4` and go to the driver editor, so on the PC build it is not a slot chooser. **Hypothesis**: the PC game plays on the first slot's file and saves it after the garage and after a session.

Port: `FrontEndSettings.saveFile` and `racerIndex` (kept between visits in `FrontEndMemory`). The viewer loads slot 0 when the game opens (a missing or unreadable file is replaced by `DEFAULT.LRS`, as `0x00443420` does with the defaults, and written), gives it to the menus, and writes it whenever the menus or a session changed it: the garage page (racer chooser with left and right; "new racer" opens `newracer`, `0x00481fe0`, a name entry; "delete racer"), the car builder and the driver editor (the current racer's record: chassis, design, driver bytes), the options (opponents → `racerCountOption`, laps → option byte 6) and a finished session (`applySessionOutcomeToSave`: best times, the beaten champion, the circuit's place, trophy and unlock). The circuit unlocks (`getCircuitUnlockFlags`) and the driver parts (`getIsPartUnlocked`) come from the loaded profile; without a save the front end's hooks (`unlockedCircuitMask`, `isEveryPartUnlocked`) apply. The file holds at most 23 racers (`0x3e00`, hypothesis) and never fewer than one. Not ported: the racer showcase and the copy and test drive buttons of the garage, the license screen's name entry (a name is typed with up, down and right in this port), a second slot, the input configurations.
